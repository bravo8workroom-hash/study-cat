## 앱 편집 규칙
<!-- en: App editing rules | f6628665372d | 9f781ad9246e -->
1. HTML 파일 하나로 유지한다. 서버, 설치, 외부 의존성은 두지 않는다(글꼴 CDN 제외).
2. 디자인: 짙은 남색 배경 #19162B, 카드 #FDFEFF, 강조 #FEB686(주황) · #FFE9C3(크림), 보조 #4D4C6B · #6A6986. 블롭(둥글고 유기적인 곡선) 스타일.
3. **고양이는 항상 검정, 예외 없음.** 색 반전이나 틴트를 하지 않는다. 어두운 배경에서는 흰색/크림 원 배경 안에 넣는다.
4. 학습 구조: 하루 20분짜리 세션 3회, 3번째 세션은 항상 복습. 간격 반복(1→3→7→14→30일)은 모든 학습 항목에 적용한다.
5. localStorage 키는 `catstudy` 하나뿐이다. **구조를 바꿀 때는 기존 사용자의 기록이 깨지지 않도록 마이그레이션 코드를 넣는다**(아이의 포인트와 연속 학습일이 사라지면 안 된다).
6. 새 내용(단어 · 문제)은 설계문서 11절의 JSON 형식을 따른다.

## 캣샘 (사용자가 「캣샘」이라고 부를 때 — 작업 흐름 확정 2026-08-08)
<!-- en: 캣샘 (when the user calls 「캣샘」 — workflow confirmed 2026-08-08) | c119e78b8d8a | bcf10bec413c -->
1. `자료수집/` 폴더의 최신 파일(사진 · 목록.json)을 직접 읽는다. 폴더가 비었거나 없으면 먼저 `node 자료가져오기.js`로 받는다(캣샘 전용 Supabase 프로젝트라서 가족 코드 입력이 필요 없다 — 고정 코드 `CAT-STUDY1`이 내장되어 있다, 2026-08-09 확정).
2. **중복 작업 금지**: `자료수집/처리기록.json`에 적힌 id는 이미 내용을 만든 자료이므로 건너뛰고, 새 자료만 처리한다. (파일이 없으면 전부 새 자료다.)
3. 읽은 자료로 문제 · 암기 세트 · 오답 노트를 **설계문서 11절의 JSON 형식**으로 만든다(아래 「내용 생성 규칙」을 따른다).
4. 결과 파일은 날짜를 붙여 저장하고, 설계실 [관리] → [파일 넣기]로 앱에 넣도록 안내한다.
5. 생성이 끝나면 이번에 처리한 자료의 id · 날짜 · 결과 파일 이름을 `자료수집/처리기록.json`에 추가한다.
- 주의: `자료수집/`에는 아이의 사진이 들어 있으므로 **절대 커밋하지 않는다**(.gitignore가 막고, `git add -f`는 금지). 앱 안의 UI 확장(숙제 연결, 목차별 오답 연결 등)은 철회된 방향이므로 다시 제안하지 않는다 — 「캣샘」(수집 → 클로드가 직접 읽고 생성 → 파일 넣기)이 확정된 계획이다.
- 다만 **관리 기능을 설계실로 옮기는 것은 별도의 확정 계획이다**(사용자 요청 2026-08-08): 설계실.html의 [관리] 패널에서 앱의 설정 · 엄마 모드 · 개발자 메뉴를 원격으로 조작한다(지시는 catstudy_plan 문서의 cmd.ops이고, 앱의 applyCmd가 한 번(1회) 적용한 뒤 S.cmdDone으로 응답한다). 파일을 넣는 정식 경로는 설계실 [파일 넣기]다(2026-08-09: 앱 설정에서 엄마 모드와 개발자 메뉴 진입점을 없앴다 — 개발자 메뉴는 테스트 모드 `index.html?test=1`로 옮겼고, 하루 새 단어 수는 autoNewPerDay로 자동이다).

## 캣샘 = 전체 학습 관리자 (2026-08-09 확정 — 「캣샘」이 설계실 단추 대신 직접 관리한다)
<!-- en: 캣샘 = overall learning manager (confirmed 2026-08-09 — 「캣샘」 manages directly instead of 설계실 buttons) | 98e299ae84b6 | 0233a6714fe4 -->
설계실.html은 읽기 전용 대시보드다. 계획을 세우고 고치고, 아이의 수준을 판단하고, 평가를 적는 일은 모두 사용자와 「캣샘」의 대화에서 이루어지며, 「캣샘」이 아래 통로로 바로 반영한다(설계실의 저장/불러오기/보내기/받기 단추는 이때 없앴다 — 자동 동기화).

1. **학습 계획 — 서버(catstudy_plan)가 원본이다.**
   `node 캣샘도구.js 계획받기` → `계획.json`의 plan/extra만 고친다 → `node 캣샘도구.js 계획올리기`.
   도구가 cmd.ops(관리 지시)와 names(노드 이름표)를 알아서 처리하므로 그 둘은 건드리지 않는다.
   설계실은 열 때 자동으로 받고, 고치면 자동으로 보내므로 별도 작업이 필요 없다. 계획.json은 커밋하지 않는다(.gitignore).
2. **아이의 성적 기록**: `node 캣샘도구.js 기록받기` → `자료수집/아이기록.json`(정답률 · 오답 · 피드백 · 포인트). 절대 커밋하지 않는다.
3. **학생 상태 — 서버(비공개 Supabase, 코드 CAT-STUDY2)가 원본이다.** 설계실 [학생 기록] 패널은 서버에서 바로 읽는다.
   `node 캣샘도구.js 학생받기` → `학생기록.json` 수정 → `node 캣샘도구.js 학생올리기`.
   내용: 수준(profile.level) · 학습 방향(direction) · 학습 방법 원칙(methods) · 평가 기록(evals) · 캣샘 일지(journal).
   - evals와 journal은 **쌓는다**. 최신이 맨 위이며 절대 지우지 않는다.
   - level과 direction은 덮어쓰되, 왜 바꿨는지 일지에 한 줄 남기고 `updated`를 갱신한다.
   - 혹시 모르니 아이의 이름 같은 개인 식별 정보는 쓰지 않는다 — 수준 · 방향 · 평가 내용만 쓴다.
4. **평가 루프(사용자가 「평가」, 「요즘 어때」 등으로 요청할 때)**: 기록받기 → 정답률 · 완료 · 피드백을 평이하게 보고 → 학생받기 후 평가를 더하고 학생올리기 → 필요하면 계획 · 교육과정 조정을 제안 → 승인되면 반영한다.
5. **교육과정 수정**: 짧은 학습 방법과 통과 기준은 curriculum.js에, 긴 자료는 curriculum/<과목>/<노드 id>.md에 둔다. 설계실에서 임시 노드를 정식으로 등록할 때는 서버 문서의 extra에서 데이터를 읽어 curriculum.js에 넣고 `node 자료파일_만들기.js`를 실행한다.
6. **아이 데이터는 git 금지** (사용자 지시 2026-08-09, 위의 절대 원칙 참조): 원본은 비공개 Supabase다 — 로컬 사본(학생기록.json · 계획.json · 자료수집/)과 캣샘도구.js는 .gitignore 대상이며, `git add -f`는 절대 금지다. 검증을 마친 curriculum.js 같은 코드만 커밋하고 푸시한다.

## 내용 생성 규칙 (문제와 오답 노트를 만들 때)
<!-- en: Content generation rules (when making questions and wrong-answer notes) | 9d98380943d3 | 81c0ca92d365 -->
1. 설명은 중1 학생이 혼자 읽고 이해할 수 있는 말로 쓴다. 한 번에 짧은 문장 하나씩.
2. 문제 변형은 원래 문제와 같은 유형, 같은 난이도(또는 조금 더 쉬움)로 만든다. 숫자와 소재만 바꾼다.
3. 오답 노트는 ① 문제 ② 아이가 쓴 답 ③ 왜 틀렸나 ④ 핵심 개념 ⑤ 비슷한 문제의 구조, 이렇게 구성한다.
   끝에는 코칭 한 줄 「노트는 이렇게 만드는 거야」가 반드시 들어간다.
   현재 인수인계 단계: [1~3주차 — 전부 쓴다] ← 진행에 따라 이 줄을 고친다

5. 자료수집/ 폴더의 파일을 읽고, 결과는 날짜를 붙여 저장한다.
